# Этап 5: проверка реального деплоя

Статус: **НЕ ВЫПОЛНЕН**. Этап 3 пропущен по просьбе пользователя: SSH не присылает приветствие. Secrets и сервер не настроены. Изменения проекта и CD пока находятся локально, поэтому GitHub Actions их ещё не выполнял.

## Порядок после восстановления доступа

1. Завершить этап 3 по `docs/deployment-plan.md` и настроить `SERVER_PATH` по `docs/cd.md`. Убедиться, что на сервере создан `.env`, а ключ хоста проверен.
2. Отправить изменения в репозиторий через обычный процесс ревью и main. Убедиться, что зелёный CI относится к этому push, затем дождаться успешного CD.
3. Скопировать полный SHA коммита из успешного CI. На сервере выполнить:

   ```bash
   bash scripts/verify-deploy.sh FULL_CI_SHA /confirmed/project/path http://127.0.0.1:8080
   ```

   Заменить SHA, путь и порт фактическими значениями. Скрипт проверяет HEAD сервера, запись успешного деплоя, чистоту Git, здоровье трёх контейнеров и HTTP 200 для главной страницы, вложенного маршрута и health endpoints. Скрипт не запускает деплой и не изменяет БД.
4. С клиентского компьютера отдельно проверить публичный адрес приложения: главную страницу, `/profile`, `/health`, `/api/system/health`. Проверка localhost на сервере не подтверждает доступность через firewall или внешний proxy.
5. В браузере проверить вход и основные сценарии. Сейчас клиент работает с mock API; его успешные операции не подтверждают запись в PostgreSQL.
6. В согласованной тестовой БД создать контрольную запись, проверить её чтение после перезапуска контейнеров и после пересоздания через Compose. Не использовать `down -v`. Проверить отсутствие публикации порта PostgreSQL на хост.
7. Проверить откат по `docs/cd.md` на согласованной тестовой версии. Сохранить исходный и итоговый SHA и результат проверки БД.

## Что записать в отчёт

- Ссылки на реальные CI/CD runs и полный SHA.
- Подтверждённый серверный каталог и публичный URL.
- Результат `verify-deploy.sh` и внешних HTTP-проверок.
- Результат браузерных сценариев, сохранности данных и отката.
- Ограничения: скрипт сравнивает checkout и запись деплоя, но не доказывает происхождение бинарников внутри уже запущенных образов. Для строгой проверки нужны метки SHA/неизменяемые образы и отдельная сверка.

До выполнения этих пунктов рабочий автоматический деплой не считается подтверждённым.
