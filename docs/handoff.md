# Передача проекта для запуска на другом компьютере

## Что подготовлено

- `backend/Dockerfile`: сборка и запуск Go-бэкенда.
- `client/Dockerfile` и `client/nginx.conf`: сборка React и раздача через Nginx.
- `compose.yaml`: клиент, бэкенд и PostgreSQL с постоянным томом.
- `.env.example`, `.gitignore`, `.dockerignore`: настройка окружения и исключение секретов.
- `.github/workflows/cd.yaml` и `scripts/deploy.sh`: сценарий автоматического деплоя для последующей настройки владельцем сервера.

Локально оба образа успешно собраны, три контейнера прошли healthcheck; `/`, `/profile`, `/health`, `/api/system/health` вернули HTTP 200. Тестовые контейнеры после проверки остановлены. Подробности: `docs/docker.md`.

## Как запустить на компьютере владельца сервера

Нужны Git, Docker с Linux-контейнерами и Docker Compose с поддержкой `--wait`. Сборка скачивает зависимости и базовые образы из интернета.

1. Получить версию репозитория с Docker-файлами. На момент подготовки этой инструкции изменения находятся локально и ещё не отправлены в GitHub.
2. В корне проекта скопировать `.env.example` в `.env`:

   PowerShell:

   ```powershell
   Copy-Item .env.example .env
   ```

   Linux/macOS:

   ```sh
   cp .env.example .env
   ```

3. В `.env` задать непустой случайный `POSTGRES_PASSWORD`. При занятом порте изменить `HTTP_PORT` (по умолчанию 8080). Пароль задаёт владелец сервера; передавать его разработчику для сборки не требуется.
4. Из корня выполнить:

   ```sh
   docker compose config --quiet
   docker compose up -d --build --wait --wait-timeout 180
   docker compose ps
   ```

5. Открыть `http://localhost:8080` и `http://localhost:8080/health`, учитывая выбранный порт. Для доступа с других компьютеров владелец настраивает firewall, сеть, внешний адрес и при необходимости HTTPS.

Остановка с сохранением данных: `docker compose down`. Не добавлять `-v`, если данные PostgreSQL нужно сохранить.

## Формат передачи

Основной вариант — передать изменения репозитория. На целевом компьютере Compose сам соберёт Docker-образы из Dockerfile. Это позволяет собрать образы под архитектуру целевого компьютера.

Dockerfile является рецептом сборки; готовый образ является отдельным артефактом Docker. Сборка и проверка образов локально выполнены, но архивы образов для передачи и публикация в container registry не выполнялись. Если требуются именно готовые образы, согласовать с владельцем архитектуру (например, linux/amd64 или linux/arm64) и способ доставки: registry или архивы `docker save`/`docker load`. Для запуска готовых образов потребуется также согласовать теги и Compose-конфигурацию с `image:`.

## Ответственность владельца сервера

- Установка Docker и настройка сети/портов, домена и HTTPS.
- Серверный `.env`, хранение данных и резервные копии.
- Для автоматизации: SSH-доступ, отдельный ключ деплоя, проверенный known_hosts, GitHub Secrets и переменная `SERVER_PATH`; инструкция в `docs/cd.md`.
- Проверка реального CI/CD и внешней доступности после получения изменений.

Текущий клиент работает с mock API. Контейнеризация не подключает его операции к реальной БД. Реальная серверная установка и автоматический деплой пока не подтверждены.
