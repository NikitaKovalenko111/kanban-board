# Интеграция frontend и backend

Актуально на **8 ноября 2026 года**. Ветка `frontend-backend-integration`, проверен backend из `783ca66` (включая изменения `1b6997d` и `4875bc3`). Backend не изменялся.

Изменены только `client/` и этот отчёт в корневом `docs/`. Проверки выполнены на отдельном временном стеке PostgreSQL/MinIO; рабочая БД, основной Compose, mobile и CI/CD не затрагивались.

## Итог

Ранее перечисленные блокирующие расхождения подключены к новым маршрутам. UI-фиксы из develop сохранены: обе темы, адаптив, модальные формы, фокус с клавиатуры, фильтры и свайпы, приоритеты, ссылки и аккаунты. Рабочие действия используют общий API-адаптер; автоматической подмены сетевых ошибок моками нет.

| Возможность | Реализованная интеграция |
|---|---|
| Вход, refresh, выход, пароль | Реальная сессия и роль; ротация токенов; отзыв актуального refresh при выходе, включая истёкший access |
| Профиль, фото, приватность | `GET/PATCH /me`, `PUT/DELETE /me/photo`, защищённый Blob для фото; реактивное обновление профиля |
| Логин и группа | Свои данные через `PATCH /me` с `username/studentGroup`; капитан меняет другого участника через `PATCH /users/:id`. Имя и фамилия не редактируются |
| Смена логина текущего пользователя | Обновляются профиль Redux, identity и login в sessionStorage; последующий вход принимает новый логин |
| Участники | Создание, блокировка/восстановление и выдача временного пароля через API |
| Проекты | `GET/POST/PATCH /projects`, сохранение `color`, состава и ролей; автор включается в members |
| Доступ к доске | Только серверный `canViewBoard`; недоступные проекты показываются по названию без запросов их деталей и задач |
| Kanban и архив | Четыре фиксированные колонки по kind, серверные UUID, создание/назначение, take/assign-to-me/move, комментарии, история и замечания |
| Приоритет | LOW/NORMAL/HIGH ↔ Низкий/Обычный/Высокий; UI и адаптер допускают изменение только до начала работы |
| Источники и результаты задачи | Файлы через multipart; ссылки через `POST /tasks/:id/attachments/links` с kind SOURCE/RESULT. `contentKind=LINK` читается без обращения к отсутствующему file |
| Источники проекта | Файлы, HTTP(S)-ссылки и удаление через API; ссылки можно приложить при создании проекта |
| Скачивание | Настоящее содержимое MinIO, защищённый `GET /files/:id`; ссылки открываются отдельно после проверки URL |
| Личные счётчики | Агрегирующий `GET /tasks`; общая доска использует полные задачи доступных проектов |
| Расписание участников | `GET /events?personId=&from=&to=`, серверная приватность masked/partial; личные события не восстанавливаются из локальных данных |
| Группы | `GET /events?group=`; несколько выбранных групп объединяются без дублей. Представитель группы больше не нужен |
| Проект события | Необязательный projectId для TEAM; выбор проекта снова доступен в расписании. PERSONAL/GROUP отправляются без projectId |
| Типы и напоминания | CRUD личных типов; все интервалы передаются без обрезки; исходные интервалы фиксируются при создании события |
| Переопределение напоминаний | `PUT /me/reminders/:itemKey` заменяет список, `minutes: []` явно отключает; `DELETE` возвращает исходные интервалы |
| Пары и уведомления | Стабильный внутренний lessonId; `GET /schedule/lessons/:id` открывает дату конкретной пары, externalId хранится отдельно |
| Прочтение уведомления | `POST /notifications/:id/read` при переходе; только подтверждённая сервером отметка. Ошибка не считается успешным чтением |
| Прочитать все | `POST /notifications/read-all`; открытие списка не отмечает записи прочитанными |

Предыдущие ошибки событий 500, auth-маршрутов 404, несовпадение lessonId, отсутствие индивидуального read, логина, цвета проекта, проектных событий и ссылок задачи больше не считаются актуальными.

## Семантика и оставшиеся ограничения

### Напоминания

Backend принимает **1–40320 минут**: значение 0 «в момент начала» всё ещё недопустимо. Клиент учитывает это ограничение.

При создании события клиент отправляет фактические интервалы выбранного типа либо индивидуальный список в `myReminders`. Они становятся исходным снимком события. Изменение типа позже не меняет этот снимок. Для существующего события действие «Вернуть исходные напоминания события» выполняет DELETE переопределения; оно возвращает снимок, а не новые настройки типа.

`GET /me/reminders` возвращает эффективную карту интервалов, включая пустой список при отключении, но не отдельный признак происхождения «исходные/переопределённые». Клиент показывает фактические интервалы и отдельное действие восстановления, не угадывает происхождение по совпадению с типом. Для сохранения такого признака между загрузками потребуется дополнительная метаинформация API. Восстановление, отключение и повторная установка уже работают.

### Расписание

`projectId` допустим только у TEAM-событий доступного проекта. Поле проекта в форме скрывается для PERSONAL/GROUP. В выбранном проекте фильтруются командные события; пары, групповые и личные события остаются общим расписанием. «Все проекты» показывает общий набор.

Границы `from/to` имеют формат YYYY-MM-DD; последний день включён. Сервер интерпретирует диапазон в UTC, поэтому клиент включает соседние дни для событий, а отображает их по локальной дате. Поля пар date/start/end используются как переданные сервером значения без дополнительной часовой зоны.

Внешняя синхронизация УУНиТ не проверялась: для воспроизводимого теста занятия подготовлены только во временной БД. Проверены ACTUAL/CACHED/UNAVAILABLE и прямой переход по стабильному UUID.

### Другие ограничения

- `GET /team` остаётся информационным: изменения названия/описания команды через PATCH API нет. Локальный успех не имитируется.
- Базовые типы событий доступны только для чтения; пользователь меняет собственные типы.
- Уведомления поступают через REST polling каждые 30 секунд и при фокусе вкладки. SSE и push-токены не подключены; это отдельные способы доставки, текущие уведомления читаются из API.
- Тема и выбранный проект по вкладкам сохраняются локально в браузере намеренно.
- Создание задачи/проекта и последующая загрузка вложений не образуют транзакцию. При частичном сбое запись может уже существовать; сообщение указывает это. Повтор загрузки результата после сбоя перехода не дублирует уже принятый файл или ссылку в пределах текущей сессии вкладки.
- Общая доска получает детали задач с ограниченной параллельностью. Архив пока фильтруется локально, без серверной пагинации; на больших объёмах это ограничивает производительность.

## API без отдельного действия в текущем UI

Новые управляющие функции сверх согласованных экранов автоматически не добавлялись.

| Backend | Состояние frontend |
|---|---|
| PATCH /me fullName | Редактирования имени нет по требованию; логин, группа, фото и приватность подключены |
| PATCH /users/:id/role, DELETE /users/:id | Глобальная роль задаётся при создании; изменения роли и удаления/обезличивания в UI нет |
| DELETE /projects/:id | Кнопки удаления проекта нет |
| PATCH/DELETE /tasks/:id | Назначение и приоритет подключены; редактирования названия/ТЗ/дедлайна и удаления нет |
| position | Отдельного управления порядком задач нет |
| PATCH/DELETE /comments/:id | Редактирование и удаление комментариев не выведены |
| DELETE /tasks/:id/attachments/:attachmentId | Отдельного удаления сохранённых вложений задачи нет |
| GET /tasks/completed, /tasks/assigned | Общий архив использует уже загруженные задачи; личные счётчики используют GET /tasks |
| PATCH/DELETE /events/:id | Создание и переходы подключены; отдельного редактирования/удаления события нет |
| SSE /notifications/stream, /me/push-tokens | Остаётся REST; web push/service worker и Android FCM из веба не добавлены |
