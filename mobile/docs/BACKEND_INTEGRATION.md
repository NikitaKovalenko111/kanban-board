# Интеграция Android с backend

## Состояние на 05.11.2026

Первый шаг реализован в `core/data/network/AuthApi.kt`: запросы `POST /api/v1/auth/login`, `POST /api/v1/auth/refresh`, `POST /api/v1/auth/logout` и `GET /api/v1/me` по `backend/docs/openapi.yaml` из ветки `backend-handlers`. После входа запрос профиля передаёт `Authorization: Bearer <accessToken>`. Токены пока живут только в памяти процесса.

`AuthApi` проверен тестом с MockWebServer. Он **ещё не подключён к экранам**: остальные репозитории приложения работают на локальном демо-сервере. Переключать только вход на настоящий backend нельзя, иначе авторизация и данные задач будут принадлежать разным источникам.

## Что требуется для следующего шага

1. Свести Swagger и реализацию backend в одну ветку. В текущем `develop` авторизация отвечает полями `access_token`, `refresh_token`, `user_id`, а Swagger ветки `backend-handlers` описывает `accessToken`, `refreshToken`, `expiresIn`, `user`. Клиент сейчас следует Swagger; точный контракт нужно подтвердить перед включением сетевого режима.
2. Дать адрес доступного dev-сервера и тестовые аккаунты. Для эмулятора локальный сервер хоста обычно доступен через `10.0.2.2`; для физического телефона нужен сетевой адрес сервера.
3. Реализовать сетевые репозитории команды, проектов, доски, задач, событий и расписания по Swagger. Подключать их вместе с сетевой сессией в `AppContainer`, сохранив отдельные сборки `clean` и `mock` для автономной демонстрации.
4. Согласовать безопасное хранение refresh-токена, обработку `401` и повторного входа. Не сохранять пароль и токены в логах.

Проверка текущего шага: `gradlew.bat testCleanDebugUnitTest assembleCleanDebug` проходит; сквозной вход в backend пока не проверен, потому что backend этой версии не запущен и контракт расходится между ветками.
