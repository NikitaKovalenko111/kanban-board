# Сверка ТЗ с мобильным приложением

Источник: документ проекта (функциональные требования Радмира, пожелания команды, Persona, задачи Самира на Спринт 3,
чек-лист проверки Алмаза). Версия приложения — `0.5.2-demo` (версии clean и mock, см. README).

Статусы: **есть** — реализовано и проверяется unit-тестами или вручную по коду; **доработано** — не работало
или отсутствовало, сделано в этой версии; **backend** — в приложении готово, но окончательно заработает только с REST API;
**не делаем** — снято командой или запланировано после лабораторной.

## Что не работало или отсутствовало и доработано

| Проблема | Что сделано |
|---|---|
| Все данные пропадали при перезапуске, вход каждый раз заново | Демо-сервер сохраняется на устройстве (`DemoStore`), вход запоминается |
| Мок-данные (9 аккаунтов, 3 проекта, 14 задач, события, демо-файлы, примерные пары) | Удалены. Остались тимлид `nikita` и участник `samir`, базовые типы событий |
| Без ИСУ и кэша показывалось выдуманное расписание | Теперь пар нет и висит предупреждение |
| Тимлид не мог удалить аккаунт | Удаление в окне участника (не себя и не человека с незакрытыми задачами) |
| Временный пароль нельзя было сменить | «Сменить пароль» в настройках аккаунта |
| Нельзя назначить второго капитана | «Сделать капитаном» / «Снять роль капитана» |
| Нельзя удалить проект | Удаление в карточке проекта, файлы удаляются с устройства |
| BUG-08: капитану нужно было идти в редактор, чтобы переназначить задачу | Кнопка «Назначить на себя» в карточке задачи |
| Ошибочно прикреплённый файл нельзя убрать | Удаление файла автором или капитаном до принятия задачи |
| Свой тип события нельзя удалить | Удаление в диалоге типа, события остаются без типа |
| Пустые экраны без подсказок при отсутствии проектов | Пустые состояния; у тимлида — кнопка «Создать проект» |
| Удалённые с устройства задачи и проекты оставляли файлы | Файлы удаляются вместе с задачей, проектом, источником, фото |
| После удаления участника история показывала «Свободная задача» | Показывается «Удалённый участник» |

## Что зависит от backend

- Общие данные для всей команды (сейчас каждое устройство — свой демо-сервер).
- Загрузка и скачивание файлов через Attachment API (QA-04).
- Push через FCM вместо локальных уведомлений.
- Эндпоинты под функции приложения: блокировка, сброс и смена пароля, роли, удаление аккаунта и проекта,
  удаление вложений, приватность расписания, уведомления. Их нужно сверить со Swagger Дениса.

## Не проверено

- Сборка: в среде разработки нет Android SDK и доступа к Maven, код не компилировался. Нужен прогон
  `./gradlew test assembleDebug`.
- Парсер ИСУ на реальной странице.
- Динамические цвета Material You (Android 12+) не реализованы — по чек-листу Алмаза это «зафиксировать как предложение».
