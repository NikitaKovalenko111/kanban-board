# Расписание ИСУ: ответственность backend

## Принятое решение

Парсер сайта ИСУ УУНиТ будет работать **на backend**. Android-приложение и веб-клиент получают уже разобранное расписание через REST API. Клиенты не обращаются к HTML-страницам ИСУ напрямую и не разбирают их разметку в рабочем сетевом режиме.

Текущий `IsuLessonsSource` и `IsuScheduleParser` в Android — временная реализация для демо-режима. Она не является целевой архитектурой. При подключении backend её заменяет сетевой `LessonsSource`, сохраняющий тот же интерфейс для экранов приложения.

## Что делает backend

1. Хранит соответствие внутренних групп `203` и `204` реальным идентификаторам групп ИСУ и формирует корректные запросы к источнику.
2. Загружает расписание ИСУ, разбирает реальные ответы и приводит пары к единой модели: дата, начало, окончание, дисциплина, вид занятия (`LECTURE`, `PRACTICE`, `LAB`), аудитория, преподаватель, группа.
3. Кэширует успешный результат и при недоступности ИСУ возвращает последнее актуальное расписание с признаком источника `CACHE`. Не подменяет отсутствующие данные выдуманными парами.
4. Отдаёт одинаковые данные мобильному и веб-клиентам. Время и дату передаёт в согласованном формате; ошибки источника сообщает отдельно от пустого дня без занятий.

## Контракт, который нужно согласовать с Денисом

Предлагаемый запрос: `GET /api/schedule/lessons?group=204&from=2026-11-02&to=2026-11-08` с `Authorization: Bearer <JWT>`. Название пути и поля ниже — предложение до утверждения OpenAPI.

```json
{
  "group": "204",
  "source": "ISU",
  "updatedAt": "2026-11-02T15:00:00Z",
  "lessons": [
    {
      "id": "lesson-123",
      "date": "2026-11-02",
      "startsAt": "2026-11-02T09:45:00+03:00",
      "endsAt": "2026-11-02T11:20:00+03:00",
      "title": "Название дисциплины",
      "kind": "LECTURE",
      "room": "Аудитория",
      "teacher": "Преподаватель"
    }
  ]
}
```

`source`: `ISU` для свежего ответа, `CACHE` для сохранённых данных, `UNAVAILABLE` при отсутствии и источника, и кэша. Для свободного дня `lessons` равен `[]`, а `source` остаётся `ISU` или `CACHE`. Клиент может хранить последний ответ локально для офлайна, но серверный кэш и разбор ИСУ принадлежат backend.

## Что меняется в Android после появления API

- Подключить сетевую реализацию `LessonsSource` через `AppContainer`, сохранив модель `LessonsSnapshot` и ленту расписания.
- Передавать выбранную группу и диапазон дат; отображать `source` и `updatedAt`, чтобы отличать свежие пары от кэша.
- Убрать прямой запрос к ИСУ и HTML-парсер из сетевого режима. Демо-реализацию можно оставить только для автономной разработки или удалить после интеграции.

На проверке 02.11.2026 текущий URL Android `https://isu.uust.ru/class_schedule/?group=204` вернул страницу выбора групп без таблицы занятий. Поэтому в эмуляторе пары не появились. Корректный источник и идентификаторы групп должен определить backend-разработчик при реализации парсера.
