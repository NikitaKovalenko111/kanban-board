# Проверка UI/UX и тем

Дата: **7 ноября 2026 года**. Ветка: `frontend-ui-fixes`.

Проверка выполнена на локальном frontend с моками. Изменения ограничены `client/`; backend, рабочая БД и DevOps не затрагивались.

## Объём проверки

- Microsoft Edge **156.0.4314.58**, Chromium, headless.
- Капитан и обычный участник, светлая и тёмная темы.
- Ширины **320, 390, 768, 1024, 1440 px**. Дополнительно проверена недельная сетка на **1920 px**.
- Основные разделы: вход, Kanban, расписание, история, участники и доступ, проекты, источники, управление проектом, профиль, обе вкладки настроек.
- Диалоги: задача, новое событие, уведомления, участник, создание задачи/проекта/аккаунта/типа события; вложенное окно ссылки и список приоритета.
- Полная матрица: **340 состояний** — `2 темы × 5 ширин × (19 состояний капитана + 15 состояний участника)`. Проведены исходный и повторные проходы.
- Отдельно пройдены **28 сквозных проверок** и **12 дополнительных проверок** файлов, длинных данных, наведения и широкого расписания.

Проверялись горизонтальное переполнение, видимость полей, подписи, фокус клавиатуры, размеры областей нажатия, состояния ошибок и контраст текста на однотонных фонах. Служебный визуально скрытый текст исключён из измерения контраста.

## Найдено и исправлено

| Проблема | Исправление |
|---|---|
| При открытии диалогов фокус оставался на странице; Tab мог уйти за окно | Общий механизм фокуса для диалогов и панели задачи: начальный фокус, удержание Tab/Shift+Tab, возврат фокуса после закрытия |
| Escape мог затрагивать несколько окон, вложенные окна конкурировали за блокировку прокрутки | Учитывается верхний слой; блокировка прокрутки снимается после закрытия последнего окна |
| Tab попадал в ссылки закрытого мобильного меню | Закрытое меню получает `inert`; открытое меню удерживает фокус и закрывается по Escape |
| После выхода и повторного входа мобильное меню могло оставаться открытым и перекрывать страницу | Состояние меню сбрасывается при смене пользователя |
| Светлая тема: второстепенный текст, подписи и основные кнопки имели слабый контраст | Скорректированы общие цвета и устаревшие жёстко заданные цвета. Например, контраст белого текста основной кнопки вырос с **4,03:1 до 5,25:1** |
| Тёмная тема: счётчик уведомлений, подпись роли в шапке, значок изменения фото и статус задачи читались хуже | Элементы используют цветовые токены соответствующей темы; сохранено различие активного/заблокированного состояния и просроченного дедлайна |
| Цветные названия типов событий могли сливаться с фоном | Названия читаются основным цветом текста; выбранные цвета сохраняются на маркировке событий |
| Поле комментария и окно задачи не имели достаточного доступного названия | Добавлены подпись поля комментария и связь заголовка с диалогом задачи; мобильная кнопка профиля получила явное имя |
| Можно было создать задачу или проект с названием из пробелов | Проверка в форме и mock API, обрезка краевых пробелов; ошибка показывается рядом с формой |
| Форма события закрывалась и очищалась до результата сохранения | Закрытие и очистка происходят после успеха. При ошибке поля сохраняются, доступна повторная отправка |
| Возврат задачи на доработку закрывал панель до результата запроса | Закрытие происходит после успеха; ошибка сохраняет замечания в форме. Повторный запрос очищает предыдущую ошибку |
| Ошибка создания проекта одновременно объявлялась в диалоге и на странице под ним | Ошибка открытой формы показывается в одном месте |
| Скрытые цветовые переключатели имели одинаковые названия | Добавлены отдельные названия цветов и видимое выделение фокуса |
| Точки навигации Kanban имели область нажатия 7×7 px | Область увеличена до **24×32 px**, визуальный размер точки сохранён; увеличены области текстовых действий |
| Мобильные поля были слишком мелкими | Размер текста вводимых значений установлен **16 px**; подписи остаются компактными |
| Длинные названия проектов растягивали сетку ролей профиля | Исправлены минимальные размеры grid/flex, переносы и обрезка. Дополнительно проверены длинные имя и логин; для обрезанных названий проектов добавлены подсказки |

## Пройденные сценарии

1. Неверные учётные данные → понятная ошибка → успешный вход.
2. Создание задачи с исполнителем, файлом и ссылкой. Вложенное окно не отправляет родительскую форму; Escape закрывает только список приоритета.
3. Участник берёт свою задачу, сдаёт файл и ссылку, оставляет комментарий. Капитан возвращает с замечанием; участник видит замечания и повторно сдаёт; капитан завершает задачу. Исходники сохраняются.
4. Поиск завершённой задачи через мобильную панель истории; сворачивание не теряет запрос.
5. Создание проекта со ссылкой, отображение единственной стрелки перехода, удаление источника через подтверждение.
6. Создание типа с несколькими напоминаниями. Создание личного события без проекта; искусственная ошибка сохранения не теряет черновик, повторное сохранение успешно.
7. Одновременный выбор командных и групповых событий без личных; свайпы расписания и Kanban настоящими touch-событиями браузера.
8. Открытие уведомлений сохраняет непрочитанное состояние; «Прочитать все» сбрасывает счётчик. Мобильное окно занимает всю высоту экрана.
9. Добавление и удаление фото без перезагрузки обновляют профиль, шапку и меню. Смена логина и группы обновляет профиль; вход по изменённому логину работает.
10. Длинное название проекта на 320/768/1440 px; длинные имя и логин в профиле и планшетной шапке; светлая и тёмная темы при наведении; семь дней расписания на 1920 px.

## Что осталось проверить вручную

- **Скачивание файла на диск в обычном браузере.** Загрузка файла, его сохранение в IndexedDB и выдача исходного содержимого через mock API подтверждены. Ссылка открывается в отдельной вкладке. Однако headless Edge в этой среде не сохранил файл в заданную папку даже при доверенном клике и разрешённом скачивании. Это ограничение проверки, а не подтверждённый дефект сайта. Нужен контрольный клик «скачать» в обычном Edge/Chrome и проверка имени и содержимого файла. При запуске скачивания элемент ссылки теперь временно добавляется в документ и затем удаляется.
- Safari/iOS, Firefox и реальные устройства с экранной клавиатурой в этой среде не запускались. Мобильные размеры и touch-события проверены в Chromium.
- Проверялась mock-ветка. Сетевые ошибки моделировались на клиенте; интеграция с настоящим backend и production-окружение не проверялись.

## UX-замечания для отдельного решения

- Системные списки выбора группы, исполнителя и сортировки сохраняют внешний вид ОС. Полная унификация потребует распространить собственный компонент выбора на остальные поля; это не добавлялось в рамках исправления подтверждённых ошибок.
- В форме новой задачи нет подтверждения ухода с несохранённым черновиком. Если нужна защита от случайного закрытия или перезагрузки, следует отдельно согласовать сохранение черновиков либо предупреждение об уходе.
